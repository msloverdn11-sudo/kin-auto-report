# 네이버 지식iN 외부유입 자동 보고 시스템

내가 쓴 블로그 주제와 관련된 네이버 지식iN 질문을 하루 3번(아침/점심/저녁, 총 10개)
자동으로 찾아서, 질문 링크 + 완성된 답변(1,000자 이내)을 카카오톡 "나에게 보내기"로
전달해주는 자동화입니다.

**중요: 이 시스템은 지식iN에 아무것도 자동으로 게시하지 않습니다.**
답변은 사람(미선님)이 카톡으로 받은 내용을 직접 확인하고 복사/붙여넣기로 올리는 용도입니다.
답변 작성 규칙은 `네이버 지식인 답글 자동화.txt` 원문을 스크립트 안(`SYSTEM_PROMPT`)에
그대로 넣어서, 그 규칙에 근거해서 만들어집니다. (단, 주제는 정부 지원금에 국한하지 않고
블로그가 다루는 모든 주제로 확장되어 있습니다.)

**외부 리소스 자동 생성 없음**: 이전 버전에서 쓰던 GitHub Gist 자동 생성 기능은
완전히 제거했습니다. 저장소에 자동 커밋하는 것도 `state/kin_state.json`(중복 방지용
아주 작은 파일) 하나뿐입니다. 카카오 메시지가 길 때는 자연스러운 지점에서
**2개의 메시지로 나눠 전송**해서, 외부 API를 추가로 호출하지 않고도 잘림 없이
전체 답변을 볼 수 있게 했습니다.

---

## 전체 흐름

1. `posts/blog_topics.json`(쓰레드 자동화의 `posts/shared.json`과 같은 구조)에 있는
   블로그 글 주제들을 하나씩 지식iN 검색 키워드로 사용 (다 써도 부족하면 기본 키워드로 보충)
2. 네이버 지식iN 검색 API로 후보 질문 수집
3. Groq(무료, llama-3.3-70b-versatile)로 "매칭된 블로그 주제와 실제 관련 있는 구체적인
   질문인지" 1차 분류 (정부 지원금·정책에 국한하지 않음 — 교통, 건강, 소비자 정보,
   여행, 심리테스트 등 블로그가 다루는 모든 주제 대상)
4. 선정된 질문은 본문을 가져오고, 신뢰할 수 있는 출처(주제에 따라 정부24/복지로/korea.kr
   또는 일반 검증된 정보처)를 조사
5. 원문 규칙(2~9단계)에 따라 답변 생성, 1,000자 초과 시 자동 축약, 한국어가 아닌
   문자(한자·일본어·기타 외국어 등)가 섞이면 자동으로 감지해서 재작성/제거
6. 카카오톡 "나에게 보내기"로 [질문 제목 + 질문 링크 + 복붙용 답변] 전송.
   답변이 길면 자연스러운 지점에서 **1/2, 2/2 두 메시지로 나눠서** 순서대로 전송
   (짧으면 메시지 1개로 끝)
7. 이미 처리한 질문 ID를 `state/kin_state.json`에 저장해 중복 방지

## 하루 스케줄 (3회 배치)

| 실행 시각(KST) | 목표 개수 |
|---|---|
| 09:00 (아침) | 4개 |
| 13:00 (점심) | 3개 |
| 19:00 (저녁) | 3개 |
| **합계** | **10개/일** |

시간이나 배분(4/3/3)을 바꾸고 싶으면 `.github/workflows/kin-auto-report.yml`의
`cron` 값과 "이번 실행의 배치 목표치 결정" 스텝의 숫자만 고치면 됩니다.

## 새 계정(msloverdn10-creator)에서 처음부터 설정하기

기존에 쓰시던 네이버/Groq/카카오/구글 API 키는 **GitHub 계정과 무관해서 그대로
재사용**할 수 있습니다. 새로 해야 하는 건 GitHub 쪽(저장소, 토큰)뿐입니다.

### 0) 계정 신뢰도 조치 (재정지 방지)

- 이메일 인증 완료 확인
- 설정에서 2단계 인증(2FA) 켜기
- 토큰은 한 번에 여러 개 만들지 말고 필요할 때 하나씩
- "Run workflow" 수동 테스트도 짧은 시간에 연타하지 말고 결과 확인하며 여유 있게

### 1) 저장소 생성

- 새 계정으로 로그인 → 새 저장소 생성 (Private 추천)
- 이 폴더 안의 파일들을 그대로 올리기: `.github/workflows/kin-auto-report.yml`,
  `scripts/kin_auto_report.py`, `scripts/refresh_kakao_token.py`,
  `posts/blog_topics.json`, `state/kin_state.json`
- `.github` 폴더는 업로드 방식에 따라 숨김 처리되어 빠질 수 있으니, 안 보이면
  "Add file → Create new file"에서 파일명 칸에 `.github/workflows/kin-auto-report.yml`
  처럼 경로를 통째로 입력해서 만드는 방법을 추천합니다.

### 2) GitHub Secrets 등록

저장소 **Settings → Secrets and variables → Actions → Secrets**에서 등록:

| 이름 | 값 | 새로 발급해야 하나? |
|---|---|---|
| `NAVER_CLIENT_ID` | 네이버 개발자센터 키 | 아니요, 기존 값 재사용 |
| `NAVER_CLIENT_SECRET` | 네이버 개발자센터 키 | 아니요, 기존 값 재사용 |
| `GROQ_API_KEY` | Groq API 키 | 아니요, 기존 값 재사용 |
| `KAKAO_REST_API_KEY` | 카카오 앱 REST API 키 | 아니요, 기존 값 재사용 |
| `KAKAO_CLIENT_SECRET` | 카카오 로그인 클라이언트 시크릿 | 아니요, 기존 값 재사용 |
| `KAKAO_REFRESH_TOKEN` | 카카오 refresh_token | 아니요, 기존 값 재사용 |
| `GOOGLE_CSE_KEY` (선택) | Google Custom Search API 키 | 아니요, 기존 값 재사용 |
| `GOOGLE_CSE_ID` (선택) | Google 검색엔진 ID | 아니요, 기존 값 재사용 |
| `GH_PAT_FOR_SECRETS` | **새 계정에서 새로 발급 필요** | 예 |

`GH_PAT_FOR_SECRETS`만 새로 만들면 됩니다: 새 계정 → Settings → Developer settings
→ Personal access tokens → Fine-grained tokens → Generate new token →
이번에 만든 저장소만 선택 → Repository permissions에서 Secrets를 Read and write로 →
생성 → 복사해서 등록.

### 3) 테스트

1. Actions 탭 → 워크플로 선택 → "Run workflow" (기본 2개만 찾도록 되어 있어 안전)
2. 카카오톡 "나와의 채팅"방에 메시지가 오는지 확인 (길면 1/2, 2/2 두 개로 옴)
3. 정상 확인되면 스케줄은 그대로 두면 됩니다

## 안내 링크(8단계) - 블로그 글 주제와 자동 매칭

`posts/blog_topics.json`에는 쓰레드 자동화(`posts/shared.json`)에 있던 48개 글이
그대로 들어있습니다. 각 항목:

```json
{
  "id": "info-001",
  "text": "K-패스 교통비 환급 제도 정리\n\n대중교통을...",
  "link_label": "신청 방법 및 상세 조건",
  "link": "https://m.site.naver.com/2a4se"
}
```

동작 방식:
1. 이 목록의 각 글 제목(본문 첫 줄)을 지식iN 검색어로 사용
2. 매칭되는 질문을 찾으면, **그 글의 `link`를 답변 B링크로 사용** (link_label도 답변 문구에 자연스럽게 반영)
3. A(숨은 지원금 안내 `m.site.naver.com/2dTSv`)와 매 답변마다 번갈아 사용
4. 블로그 주제로 목표 개수를 못 채우면, 기본 키워드(`FALLBACK_KEYWORDS`)로 보충 검색
   - 이 경우엔 매칭된 글이 없으므로 B링크는 대표 블로그 링크(`LINK_B_DEFAULT`)로 대체됩니다

**새 블로그 글을 쓰시면**: `posts/blog_topics.json`에 같은 형식으로 항목을 추가해주세요.
쓰레드 자동화의 `posts/shared.json`에 이미 추가하신 내용이 있다면, 그 항목을
그대로 복사해서 넣으시면 됩니다 (`image` 필드는 빼도 됩니다).

## 파일 구성

```
.
├── .github/workflows/kin-auto-report.yml   # 하루 3회 실행 스케줄
├── posts/
│   └── blog_topics.json                    # 블로그 글 주제 목록 (검색 키워드 + 답변용 링크 출처)
├── scripts/
│   ├── kin_auto_report.py                  # 메인 로직
│   └── refresh_kakao_token.py              # 카카오 토큰 갱신
└── state/
    └── kin_state.json                      # 처리 이력(중복 방지), 자동 커밋됨
```

## 주의할 점

- 지식iN 질문 본문 크롤링은 페이지 구조가 바뀌면 실패할 수 있습니다.
  실패해도 자동으로 검색 스니펫만으로 답변을 만들도록 되어 있어 전체가 멈추지는 않습니다.
- 하루 10개를 실제로 지식iN에 직접 올리실 때도, 짧은 시간에 몰아 올리기보다
  자연스럽게 시간 간격을 두고 올리시는 걸 권장드려요(네이버 어뷰징 탐지 리스크 관리 차원).
- 카카오 전송이 실패하면(레이트리밋, 토큰 만료 등) 실패로 기록하고 다음 질문으로 넘어갑니다.
  긴 답변의 경우 1/2, 2/2 중 하나만 전송 성공하고 나머지가 실패할 수도 있는데,
  이 경우도 로그에 실패로 남습니다.
